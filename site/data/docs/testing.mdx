# Testing by runtime

Orez crosses PostgreSQL, SQLite, WebAssembly, and Zero protocol surfaces. Each runtime documents evidence next to the contract it exercises, so a passing test has a clear scope.

<CardGrid>
  <DocCard href="/docs/node/testing" title="Node testing">
    Unit and process-level evidence for orchestration, the PGlite compatibility layer,
    real Postgres, recovery, and SQLite selection.
  </DocCard>
  <DocCard href="/docs/orez-lite/testing" title="Orez Lite testing" badge="Preview">
    Deterministic model, differential, fault, permissions, retention, WASM-host, and
    deployment qualification layers.
  </DocCard>
</CardGrid>

## Reading an evidence claim

For each claim, the runtime page identifies the layer that ran, the implementation boundaries it crossed, and the asserted result. Process scenarios establish the behavior of a running stack under the stated setup.
